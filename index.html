Docker چییە؟

Docker کۆدی application، dependency و شێوازی جێبەجێکردنی لە container ـێکی جیاکراوەدا دەخات. ئامانج دووبارەبوونەوەی ئەنجامە، نە تەنها چارەسەری «لەسەر کامپیوته‌ری من کار دەکات».

PACKAGE

Image

وێنەیەکی immutable ـە؛ layers ـی فایل و metadata ـە کە container لێ دروست دەبێت.

PROCESS

Container

جێبەجێکردنی image ـە؛ process ـەکی ڕاستەقینەیە، نە virtual machine ـێکی بچووک.

CONTRACT

Compose

ناسنامەی app، database، network و volume ـە پەیوەندیدارەکانە.

کێشەهۆکارڕێچکەی Docker
جیاوازی environmentversion ـی runtime جیاوازەimage ـی pinned و reproducible
deploy ـی دەستیزانیاری لە یادەوەری کەسێکەDockerfile و Compose وەک code
resource conflictسرویسەکان پێشبڕکێ دەکەنnamespace و cgroup
تێبینی: container security boundary ـێکی تەواو نییە؛ kernel ـی host هاوبەشە. بۆ isolation ـی زۆر بەهێز، VM و policy ـی دروست هەڵسەنگێنە.

داتا: volume و bind mount

writable layer ـی container بە دوای لادانی container ـەکە نامێنێت. داتا لە lifecycle ـی app جیا بکە.

Named volume

Docker بەڕێوەی دەبات؛ بۆ database و data ـی persistent زۆرجار باشترە.

Bind mount

فۆڵدەری host بە container دەبەستێت؛ بۆ development و hot reload بەکاربهێنە.

data.sh
$ docker volume create pgdata
$ docker run -d --name db \
    -e POSTGRES_PASSWORD=devpass \
    -v pgdata:/var/lib/postgresql/data postgres:16-alpine
$ docker volume inspect pgdata
$ docker run --rm -v "$PWD":/work -w /work alpine ls
Backup تەنها volume نییە: dump ـی application-consistent دابین بکە و restore ـەکە تاقی بکەوە.

Networking

پۆرتی ناو container و پۆرتی host جیاوازن. سرویسەکان لە network ـی هاوبەش بە ناوی service پەیوەندی دەکەن.

network.sh
$ docker network create app-net
$ docker run -d --name redis --network app-net redis:7-alpine
$ docker run --rm -it --network app-net redis:7-alpine redis-cli -h redis ping
# ناوی redis DNS ـی ناوخۆییە، پێویست بە IP نییە

bridge

network ـی ناوخۆیی بۆ سرویسەکانی یەک host؛ پۆرت بە -p publish دەکرێت.

host

namespace ـی host بەکاردێنێت؛ isolation کەم دەکات.

none

بۆ job ـی جیاکراو کە پێویستی بە network نییە.

پۆرت: 127.0.0.1:8080:80 تەنها local ـە؛ 8080:80 هەموو interface ـەکان bind دەکات.

Dockerfile ـی باش

Dockerfile کۆدی build ـە. ترتیب، cache، context و layers لە performance و security کاریگەری هەیە.

Dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build
FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
USER nginx

یاساکان

base ـی بچووک، dependency ـی پینکراو، user ـی non-root و .dockerignore.

BuildKit

docker buildx build --progress=plain --tag app:dev . بۆ cache و multi-platform.

Compose: کۆمەڵە سرویس

Compose بۆ local development و workflow ـی multi-container ـە. healthcheck و retry جیاوازی start و ready چارەسەر دەکەن.

compose.yaml
services:
  app:
    build: .
    ports: ["8080:8080"]
    environment:
      DATABASE_URL: postgres://app:secret@db:5432/app
    depends_on:
      db:
        condition: service_healthy
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
      retries: 10
volumes:
  pgdata:
compose lifecycle
$ docker compose config
$ docker compose up --build -d
$ docker compose ps
$ docker compose logs -f app
$ docker compose down

Resource، health و shutdown

Production container دەبێت سنووری هەبێت و بتوانێت بڵێت چۆنە. healthcheck جێگەی monitoring ـی تەواو ناگرێت.

runtime-policy
$ docker run -d --name api --memory=512m --cpus=1.5 \
    --restart=unless-stopped --stop-timeout=20 \
    --health-cmd='curl -fsS http://localhost:8080/health || exit 1' \
    --health-interval=10s --health-retries=3 ghcr.io/acme/api:1.4.0

Liveness

Process زیندووە؟ ئەگەر نا restart. پشکنینەکە سادە و local بێت.

Readiness

ئامادەی وەرگرتنی traffic ـە؟ dependency ـەکان لەبەرچاو بگرە.

SIGTERM: connection ـەکان داخە و بە shutdown ـی ئارام exit بکە؛ process ـی یەکەم بە دروستی signal وەربگرێت.

CI/CD و deploy

Pipeline ـێکی باش هەمان artifact ـەکە test، scan، sign و deploy دەکات؛ بۆ هەر environment image ـی جیاواز build مەکە.

1. Testunit و integration
2. Buildimage + SHA
3. Verifyscan و SBOM

Pipeline

Rollback

Vercel: ئەم repo ـە static HTML ـە؛ Vercel build command ـێکی پێویست نییە و دوای push خۆکارانە redeploy دەکات.

Capstone: ئەپێکی production-ready

app، database و worker دروست بکە و لە local ـەوە تا release بڕۆ. ئەمە definition of done ـە:

  • Dockerfile ـی multi-stage و reproducible
  • health endpoint و graceful shutdown
  • Compose بۆ app، db و worker
  • volume و backup/restore script
  • network ـی public و internal جیا
  • config لە secret جیا و .env commit نەکرێت
  • image بە SHA و vulnerability scan
  • resource limit، non-root و read-only
  • logs و metrics ـی بنەڕەتی
  • rollback و incident runbook
definition-of-done
$ docker compose config
$ docker compose build --pull
$ docker compose up -d
$ docker compose ps
$ curl --fail http://localhost:8080/health
$ docker compose down
# build reproducible، runtime observable، rollback ناسراو.
ئامانجی senior: تەنها command لەبەر مەکە؛ trade-off ـی security، performance، cost و reliability بە data بڕیار بدە.
